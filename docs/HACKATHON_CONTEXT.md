# FootballIQ — ChatGPT-to-Codex project handoff (October 19, 2026)

## Background / motivation
The user is participating in the Microsoft × Premier League Inside the Game Developer Hackathon. We discussed the rules and chose to build FootballIQ as a solo-friendly, roughly 3–4-hour/day effort. Project focuses on explainable football intelligence from synthetic football events, not a generic chatbot.

## Key challenge requirements, based on user's pasted brief
- The event feed **must use synthetic, football-realistic data**. Real Premier League match data is not distributed to participants.
- Transform passes, shots, tackles, possession changes, and changes in pressure into useful insights and narratives.
- Project must be newly built, use applicable Microsoft AI technologies, and provide functioning software.
- Submission: project description/pitch, publicly accessible video **under 2 minutes** showing app working, and public GitHub source URL.
- Deadline: Oct 27, 2026 at 11:59 PM PT; winner announcement Nov 20.
- Judging: technological implementation 20%; agentic design/innovation 20%; real-world applicability 20%; user experience/presentation 20%; category adherence 20%.
- Primary target category: Best Multi-Agent Orchestration. Secondary: Best Use of Microsoft Foundry. Aspirational: Grand Prize.
- Verify registration and eligibility specifics on official rules before relying on them.

## Agreed product: FootballIQ
A fictional live football game generated by Python. A dashboard shows match progression, raw evidence, stats, momentum/pressure signals, grounded narratives and recaps. Fan/analyst audience modes and English/Kazakh output are differentiators.

## Planned architecture (flexible)
- Python synthetic simulator, JSON/JSONL events, stable seeded generation.
- Python deterministic validation, aggregates and rolling windows; optional Azure Functions ingestion.
- Microsoft Foundry plus Microsoft Agent Framework orchestration: Stats Agent (deterministic tools), Tactical Agent (explain patterns), Commentary Agent (narrative), Personalization Agent (language + audience). Distinct responsibilities with structured handoffs, shared state, and fallbacks.
- Streamlit first for web interface. Azure hosting later (Container Apps is a candidate), optional Fabric only if spare time.
- Keep secrets out of repository, configure budgets/alerts, validate factual outputs.

## Phase roadmap discussed
1. Foundation: registration/GitHub, event schema, seeded 90-minute synthetic match, tests, Foundry account setup.
2. Analytics: ingest/replay, rolling metrics, pressure/momentum signals, dashboard.
3. AI: Foundry access, genuine agent orchestration, evidence-grounded explanations, failure handling.
4. UX: fan/analyst, English/Kazakh, key-moment cards, halftime/final recaps.
5. Deploy/test/document and submit a <2-minute video and public code.

## Important synthetic simulator caveats
The existing event generator is intentionally simplified; don't equate event count with possession percentage. Implement coherent transitions, period-level pressure, and evidence-backed calculations in Phase 2. Avoid falsely claiming player-tracking precision or true xG model accuracy.
